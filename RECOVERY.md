## What needs backing up

| Asset | Path (relative to project root) | Why irreproducible |
|---|---|---|
| Cached buoy observation series | `dashboard_buoy_data.rds` | ERDDAP keeps a rolling ~2-year window for many buoys; older observations are pruned at the source. Refetching after a gap loses history. |
| Computed return levels | `dashboard_return_levels.rds` | Derived from the above; if the source obs are lost, this can't be regenerated to identical values. |
| Summary statistics | `dashboard_stats.rds` | Same — derived from ERDDAP-cached series. |
| ERDDAP raw cache (any) | `inst/extdata/*` (parquet/duckdb/CSV) | Provider-side rolling window applies. |
| `_targets/` pipeline cache | `../_targets/` (lives at the parent level) | Mostly reproducible from sources, BUT only if the sources are preserved. Treat as derived: rebuild only if the RDS sources above are intact. |

Reproducible (do NOT need backup): `R/` source code (in package git), `DESCRIPTION`, `README.qmd`, `docs/` (re-rendered), `ctx/` (regenerated by pkgctx).

## RPO / RTO

| Asset | RPO | RTO | Bottleneck |
|---|---|---|---|
| `dashboard_*.rds` | 7 days | ~5 min | Backup transfer speed |
| ERDDAP cache | 7 days | ~5 min | Same |

7-day RPO is more lenient than llmtelemetry because the data is also re-fetchable (within the ERDDAP window) — gaps narrower than the provider window can be backfilled live.
